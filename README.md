## Пять функций

| Функция | Назначение |
|---|---|
| `generate_password(length=12)` | Пароль заданной длины: минимум 4 символа, обязательно строчная и заглавная ASCII-буква, цифра и знак пунктуации. |
| `generate_passwords(count=5, length=12)` | Список паролей: количество не меньше 1; длина как у generate_password. Совпадения допустимы. |
| `generate_pin(length=6)` | PIN как строка ASCII-цифр; минимум 1 цифра, ведущие нули сохраняются. |
| `password_strength(password)` | Учебная оценка `weak`, `medium` или `strong`. |
| `is_strong_password(password)` | True, если пароль соответствует учебному критерию strong. |

Уровни: strong — минимум 12 символов и все четыре группы; medium — минимум 8 символов и не менее трёх групп; остальные случаи — weak. Оценка состава и длины не оценивает словарные пароли или реальную устойчивость к атакам. Пробелы и Unicode входят в длину, но не относятся к четырём ASCII-группам.

Длины и количество должны быть именно int: bool, дробные числа и строки отвергаются с TypeError. Слишком маленькие значения вызывают ValueError. Функции оценки принимают строки, включая пустую; остальные типы вызывают TypeError. Случайные символы выбираются через secrets, пароль перемешивается через secrets.SystemRandom.

## Запуск

Открыть терминал в этой папке:

```powershell
python -m unittest -v
python run_mutations.py
```

Пример использования:

```python
from password_generator import (
    generate_password, generate_passwords, generate_pin,
    password_strength, is_strong_password,
)

password = generate_password(16)
print(password)
print(generate_passwords(3, 16))
print(generate_pin(6))
print(password_strength(password))
print(is_strong_password(password))
```

## Тесты и мутации

Набор из 18 методов unittest написан до мутационного запуска и после него не изменялся. Внутри методов проверяются многочисленные случаи через subTest: все 15 непустых сочетаний групп, длины возле 4, 8 и 12, неверные типы и значения, все знаки string.punctuation, Unicode, пробелы, пустая строка, число паролей, ведущий ноль и возможность получить цифру 9.

Тесты свойств случайного результата не требуют, чтобы два пароля обязательно отличались. Для проверки отдельных сценариев источник случайности подменяется: результаты таких проверок воспроизводимы.

run_mutations.py автоматически изменяет по одному узлу синтаксического дерева и запускает тот же набор тестов. Исходный модуль и тесты не изменяются. Операторы: изменение границ сравнений и отрицание сравнений, сдвиг целочисленных констант, замена уровня оценки, and/or, +/- , удаление not, any/all, удаление цифры 9 из алфавита. Изменяются и значения по умолчанию.

Проверено на Python 3.12.14: 18 тестов проходят; 50 мутантов обнаружено, 0 выжило, 0 некорректных. Результаты каждого мутанта с обнаружившими его тестами — в mutation_results.json. Результат 100% относится только к этому ограниченному набору операторов: другой инструмент может создавать другие мутации. Скрипт является собственным учебным инструментом, не MutPy, PIT или Stryker.

Покрытие исполняемых строк основного модуля измерено стандартным модулем trace: 41 из 41 строки, 100%. Это покрытие строк, не ветвей. Сводка — в coverage_results.json. Для повторного измерения стандартным инструментом можно запустить `python -m trace --count --summary --missing --file coverage.dat test_password_generator.py`; trace учитывает и другие исполняемые файлы, поэтому в сводке выделяйте password_generator.

## Версия с намеренной ошибкой

initial_with_bug/password_generator.py сохраняет исходную версию для первой части задания. В ней generate_pin использует алфавит 012345678 и не может выдать цифру 9. Тот же неизменный набор тестов обнаруживает дефект. В основном password_generator.py ошибка исправлена: используется string.digits. Карточка дефекта и результаты проверки исходной версии сохранены отдельно.

Для индивидуальной работы последовательность такая: зафиксировать исходную версию, выполнить тестирование, оформить дефект, исправить код, повторить тестирование, провести мутации, описать результаты. Поскольку все выбранные мутанты обнаружены исходным набором тестов, доработка тестов не потребовалась. В отчёте укажите это фактически, без выдуманного улучшения показателей.

Титульный лист, данные автора и дисциплины, оформление по требованиям преподавателя и полный учебный отчёт в этот комплект не входят.
